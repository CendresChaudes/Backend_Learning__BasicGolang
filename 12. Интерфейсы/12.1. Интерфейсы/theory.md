# 12.1. Интерфейсы

Интерфейс — список методов. Тип подходит под интерфейс, когда у него есть все методы из этого списка. Совпадение имён, аргументов и результатов достаточно. Отдельно «подписываться» на интерфейс не нужно.

Так одна функция принимает и диск, и облако. Ей важен метод, а не имя типа. Это и есть внедрение зависимости: функцию не привязывают к одному конкретному типу, значение передают снаружи.

## Список методов

```go
type Labeler interface {
	Label() string
}

type Disk struct {
	Name string
}

func (d Disk) Label() string {
	return "disk:" + d.Name
}

type Cloud struct {
	Name string
}

func (c Cloud) Label() string {
	return "cloud:" + c.Name
}

func place(item Labeler) string {
	return item.Label()
}
```

`place` не знает, диск это или облако. Она вызывает `Label`. И `Disk`, и `Cloud` подходят, потому что метод есть у обоих.

## error

`error` — встроенный интерфейс с одним методом:

```go
type error interface {
	Error() string
}
```

Свой тип становится ошибкой, когда у него есть метод `Error() string`. Функция может вернуть это значение как `error`. Вызывающий код смотрит на `nil` и читает текст через `Error()`, не зная конкретный тип.

## Что запомнить

- Интерфейс описывает методы, не поля.
- Тип подходит сам, если методы совпали.
- Функция принимает интерфейс и работает с любым таким типом.
- `error` — интерфейс с методом `Error() string`.
