# 12.2. Внедрение зависимостей

Зависимость — значение, без которого функция не может сделать работу. Для подписи файла это коробка `FileBox`: в ней лежит имя.

Внедрение зависимости — вызов, при котором это значение передают снаружи. Функция его не создаёт. Кто вызвал функцию, тот и выбрал файл.

Тип из прошлого урока в этом файле описывают снова: каждый урок собирается отдельно.

```go
type FileBox struct {
	Name string
}

func (b FileBox) Title() string {
	return b.Name
}
```

`Title` возвращает имя из поля.

## Функция создаёт коробку сама

```go
func fixed() string {
	box := FileBox{Name: "notes.txt"}
	return box.Title()
}
```

`fixed` сама пишет `"notes.txt"`. Чтобы получить другое имя, придётся менять тело `fixed`. Вызов снаружи на это не влияет.

## Имя приходит аргументом

```go
func title(box FileBox) string {
	return box.Title()
}
```

`title` принимает готовую коробку. Внутри нет `FileBox{...}`. Функция пользуется тем, что ей дали, и вызывает `Title`.

```go
disk := FileBox{Name: "vault.json"}
text := title(disk)
```

`disk` собран снаружи. `title(disk)` передаёт его в функцию. В `text` будет `"vault.json"`. Другой файл — другая коробка в этом вызове, тело `title` то же.

Так устроен и backend-код. Обработчик запроса получает хранилище аргументом. Где лежат данные, решает тот, кто собирает программу, а не каждая функция по пути.

## Что запомнить

- Зависимость — значение, которое нужно функции. Здесь это `FileBox`.
- Внедрение: значение создают снаружи и передают аргументом.
- Функция вызывает метод у аргумента и не собирает коробку внутри.
- Другой файл подставляют другим аргументом, тело функции не трогают.

## Что сделать

Заполни `tasks.go`. `FileBox` и функции `title`, `mark`, `ready` опиши на уровне пакета. Запуск: `go run .`. Проверка: `go test .`.
