# 15.7. Debug приложения

Debug — просмотр того, что программа сделала на самом деле. Для HTTP-клиента это метод, полный адрес и код статуса. По одной строке `Moscow: ясно` не видно, какой URL ушёл и что ответил сервер.

## Строка запроса

`fmt.Sprintf` собирает строку из образца и значений.

```go
rawURL := "https://api.weather.local/v1?city=Moscow"
line := fmt.Sprintf("GET %s -> %d", rawURL, 200)
```

`%s` заменяется на строку, `%d` — на целое число. В `line` будет `GET https://api.weather.local/v1?city=Moscow -> 200`.

Эту строку печатают, когда ответ выглядит странно. При запуске через `go run .` она видна в терминале.

## Когда её показывать

Удачный ответ и так печатают отчётом. Debug-строка нужна, когда статус другой.

```go
if code != 200 {
	return fmt.Sprintf("GET %s -> %d", rawURL, code)
}
return "Moscow: ясно"
```

`code != 200` — статус не равен 200. Для `404` функция вернёт `GET https://api.weather.local/v1?city=Moscow -> 404`. Для `200` вернёт короткий отчёт `Moscow: ясно`.

## Точка останова

Точка останова (breakpoint) — отметка на строке в редакторе. Запуск в режиме отладки останавливается на ней. Можно посмотреть переменные `rawURL` и `code` до `return`.

Строка из `Sprintf` остаётся для обычного запуска, когда отладчик не включён.

## Что запомнить

- Debug HTTP-клиента показывает метод, URL и статус.
- Образец строки: `GET %s -> %d`.
- Статус `200` — печать отчёта. Другой статус — печать debug-строки.
- Breakpoint останавливает программу на строке и показывает переменные.

## Что сделать

Заполни `tasks.go`. Адрес во всех заданиях один: `https://api.weather.local/v1?city=Moscow`. Запуск: `go run .`. Проверка: `go test .`.
