# 16.3. Debug теста

Debug теста — чтение провала. Тест уже сказал `FAIL`. Дальше нужно увидеть, какой тест упал и чем `got` отличается от `want`.

## Текст провала

`t.Errorf` пишет строку в отчёт. Образец показывает оба значения.

```go
t.Errorf("получилось %q, нужно %q", got, want)
```

`%q` подставляет строку в кавычках. В терминале это выглядит так:

```text
--- FAIL: TestTask1 (0.00s)
    tasks_test.go:11: получилось "ясно", нужно "дождь"
```

По строкам:

- `FAIL` — проверка не сошлась.
- `TestTask1` — имя функции теста.
- Дальше файл и номер строки, где стоит `t.Errorf`.
- В конце факт и ожидание. Их и сравнивают глазами.

Такую же строку можно собрать заранее через `fmt.Sprintf`. Образец тот же, функция возвращает готовую строку.

```go
msg := fmt.Sprintf("получилось %q, нужно %q", "ясно", "дождь")
```

В `msg` будет `получилось "ясно", нужно "дождь"`.

## Подробный вывод

Обычный `go test .` прячет успешные тесты и показывает упавшие. Флаг `-v` включает подробный режим.

```bash
go test -v .
```

`-v` значит verbose, подробный. У каждого теста появится своя строка: `PASS` или `FAIL`, затем имя.

Имя для такой строки собирают сами, когда хотят напечатать итог:

```go
line := "PASS " + name
```

Для имени `TestTask1` в `line` будет `PASS TestTask1`. Если тест не сошёлся, первое слово меняют на `FAIL`.

## Журнал внутри теста

`t.Logf` пишет заметку в журнал теста. `f` на конце значит то же, что у `fmt.Sprintf`: строка собирается по образцу.

```go
t.Logf("code %d", code)
```

Эта строка видна в двух случаях: тест упал или запуск был с `-v`. Успешный `go test .` без флага журнал не печатает.

## Что запомнить

- Провал показывает имя теста, файл, строку, `got` и `want`.
- `%q` ставит кавычки вокруг строки. Пробелы так не теряются.
- `go test -v .` печатает `PASS` или `FAIL` у каждого теста.
- `t.Logf` пишет заметку. Её видно при падении и при `-v`.

## Что сделать

Заполни `tasks.go`. Запуск: `go run .`. Проверка: `go test .`. После решения запусти ещё `go test -v .` и найди строку `PASS` у каждого теста.
