# 16.4. Негативный тест

Позитивный тест даёт функции обычный вход и ждёт удачный ответ. Город `Moscow` — в результате есть отчёт.

Негативный тест даёт плохой вход и ждёт отказ. Пустой город — строка запроса пустая. Код `404` — успехом его не считают.

Оба теста нужны одной функции. Проверка только на `Moscow` не увидит пустую строку.

## Пустой город

Вход негативного теста — пустая строка. Ожидание — тоже пустая строка: запрос собирать рано.

```go
func TestEmptyCity(t *testing.T) {
	got := cityQuery("")
	want := ""
	if got != want {
		t.Errorf("получилось %q, нужно %q", got, want)
	}
}
```

`cityQuery("")` — Act с плохим входом. `want` здесь `""`. Если функция вернёт `city=`, тест упадёт: отказ выглядит иначе, чем пустая строка.

Рядом с ним позитивный тест вызывает ту же функцию с `Moscow` и ждёт `city=Moscow`.

## Чужой статус

Успех в этом клиенте — статус `200`. Остальные коды — негативные случаи.

```go
ok := code == 200
```

`==` сравнивает два числа. Выражение имеет тип `bool`. Для `200` в `ok` будет `true`. Для `404` будет `false`.

Отдельный тест на `404` как раз проверяет эту `false`.

## Пустые поля отчёта

Отчёт без города или без текста погоды собирать не из чего. Такой вход возвращает короткую метку отказа.

```go
if city == "" || text == "" {
	return "нет данных"
}
```

`||` значит «или». Условие истинно, если пустой город или пустой текст. Тогда функция возвращает `нет данных`.

Позитивный вызов с `Moscow` и `ясно` это условие пропускает и возвращает `Moscow: ясно`.

## Что запомнить

- Позитивный тест ждёт удачный ответ на обычном входе.
- Негативный тест ждёт отказ: пустую строку, `false` или текст вроде `нет данных`.
- У одной функции оба теста. Вход у них разный.
- Статус `200` — `true`. `404` проверяют отдельно, там ждут `false`.

## Что сделать

Заполни `tasks.go`. В каждом задании есть и удачный вход, и плохой. Запуск: `go run .`. Проверка: `go test .`.
