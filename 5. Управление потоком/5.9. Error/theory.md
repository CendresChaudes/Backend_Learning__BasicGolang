# 5.9. Error

`error` — тип для сообщения о неудаче. Функция возвращает его рядом с результатом. Вызывающий код сам решает, что делать. Программа при этом не останавливается.

## Текст ошибки

Пакет `errors` создаёт ошибку из строки. Его подключают через `import`.

```go
import "errors"

err := errors.New("пустой порт")
```

`errors.New` возвращает значение типа `error`. Внутри лежит текст `"пустой порт"`.

Метод — функция, привязанная к значению. Его вызывают через точку. У `error` есть метод `Error`: он отдаёт текст обратно.

```go
text := err.Error()
```

В `text` будет `"пустой порт"`.

## nil

`nil` значит «значения нет». Для `error` это сигнал: ошибки не случилось.

```go
var err error
```

Пока в `err` ничего не положили, там `nil`. Нулевое значение типа `error` — как раз `nil`.

Проверяют так:

```go
if err != nil {
	return err.Error()
}
```

`err != nil` истинно, когда ошибка есть. Пока там `nil`, входить в `if` не нужно.

## Два результата

Обычная форма: сначала полезный результат, вторым — `error`. Если работы не вышло, на месте результата оставляют нулевое значение, а ошибка объясняет почему.

```go
func divide(a, b int) (int, error) {
	if b == 0 {
		return 0, errors.New("деление на ноль")
	}
	return a / b, nil
}
```

`return 0, errors.New(...)` отдаёт заглушку `0` и ошибку. Делить на ноль нельзя, поэтому настоящего частного нет.

`return a / b, nil` отдаёт частное и `nil`: ошибки нет.

Вызов сначала смотрит на ошибку:

```go
result, err := divide(10, 0)
if err != nil {
	fmt.Println(err.Error())
}
```

Пока `err` не равен `nil`, `result` не используют. Там заглушка, а не ответ.

## Что запомнить

- `error` сообщает о неудаче и не останавливает программу.
- `errors.New` создаёт ошибку из текста. Метод `Error` возвращает этот текст.
- `nil` значит, ошибки нет.
- Рядом с результатом ошибку возвращают второй величиной. Сначала проверяют её.

## Что сделать

Заполни `tasks.go`. Ошибку создавай через `errors.New`. Запуск: `go run .`. Проверка: `go test .`.
