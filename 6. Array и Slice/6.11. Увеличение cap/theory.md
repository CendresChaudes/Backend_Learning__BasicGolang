# 6.11. Увеличение cap

`append` сначала смотрит, есть ли свободная ячейка. Свободная ячейка есть, пока `len` меньше `cap`. Тогда новый элемент пишется в тот же массив: `len` растёт на один, `cap` остаётся прежним.

Когда `len` уже равен `cap`, писать некуда. `append` создаёт новый массив больше прежнего, копирует туда старые элементы и дописывает новые. У среза, который она возвращает, `cap` больше старого.

Точный новый размер выбирает Go. Его читают через `cap`, а не считают формулой. Для среза из двух `int`, у которого `len` и `cap` равны `2`, один добавленный элемент даёт `cap`, равный `4`.

## Место ещё есть

```go
codes := make([]int, 2, 4)
codes[0] = 200
codes[1] = 404
codes = append(codes, 500)
```

`len` был `2`, `cap` был `4`. Третья ячейка в том же массиве свободна. После `append` `len` равен `3`, `cap` остаётся `4`. `codes[2]` равен `500`.

## Места нет

```go
codes := make([]int, 2, 2)
codes[0] = 200
codes[1] = 404
grown := append(codes, 500)
```

Здесь `len` равен `cap`. `append` собирает новый массив. `grown` смотрит уже в него: `cap(grown)` равен `4`, `grown[2]` равен `500`.

`codes` при этом хранит прежнее окно. Результат `append` в неё не записывали, поэтому `len(codes)` остаётся `2`. Третий элемент читают у `grown`.

Если дальше работать нужно уже с длинным срезом, результат сохраняют в ту переменную, которой пользуются: `codes = append(codes, 500)`.

## Что запомнить

- Пока `len` меньше `cap`, `append` пишет в тот же массив. `cap` не меняется.
- Когда `len` равен `cap`, `append` возвращает срез на новый, больший массив.
- Прежнее имя хранит старые `len` и `cap`, пока в него не запишут результат `append`.
- Новый `cap` узнают вызовом `cap`.
