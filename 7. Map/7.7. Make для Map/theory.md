# 7.7. Make для Map

`make` создаёт пустую map, в которую уже можно писать. У среза второй аргумент `make` задавал длину, а третий — вместимость. У map второй аргумент устроен иначе: это подсказка, сколько пар ожидается.

## Пустая map

```go
codes := make(map[string]int)
```

`make` здесь получает только тип. Пар ещё нет, `len(codes)` равен `0`. Запись уже возможна.

```go
codes["ok"] = 200
```

После этой строки в map одна пара. `len(codes)` равен `1`. Panic нет: `make` создал map, это уже не nil.

Пустой литерал `map[string]int{}` даёт такой же старт: ноль пар и возможность записи. `make` без второго аргумента и этот литерал для обычной работы равносильны.

## Подсказка числа пар

```go
codes := make(map[string]int, 8)
```

Число `8` говорит, сколько пар программа примерно положит. `len(codes)` при этом всё равно `0`. Подсказка не заполняет map нулями и не становится пределом: девятая пара тоже запишется.

Смысл подсказки в памяти. Map заранее готовит место, и при росте реже перекладывает пары в новый участок.

Вместимость map через `cap` не читают. `cap` определён для массива и среза. Для map вызов `cap` не компилируется.

## nil

```go
var codes map[string]int
```

Объявление без `make` и без литерала оставляет nil. `len(codes)` равен `0`. Чтение `codes["ok"]` возвращает `0` и программу не останавливает.

Запись в эту же переменную вызывает panic. Пары некуда класть: map ещё не создана. Перед первой записью её получают литералом или `make`.

## Что запомнить

- `make(map[K]V)` создаёт пустую map. Запись в неё безопасна.
- Второй аргумент — подсказка числа пар. На `len` он не влияет и лимитом не является.
- `cap` для map не вызывают.
- Чтение из nil-map возвращает ноль. Запись в nil-map вызывает panic.
