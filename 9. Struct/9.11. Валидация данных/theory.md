# 9.11. Валидация данных

Валидация — проверка данных до того, как из них соберут struct. Плохое значение в конструктор не проходит. Функция возвращает ошибку, а готовый инстанс — только когда проверка прошла.

Ошибка здесь — тип `error` из урока про ошибки. Её создают через `errors.New`. Рядом с результатом struct стоит вторым значением.

```go
import "errors"

type Ticket struct {
	Price int
}

func NewTicket(price int) (Ticket, error) {
	if price <= 0 {
		return Ticket{}, errors.New("цена")
	}
	return Ticket{Price: price}, nil
}
```

`(Ticket, error)` — два результата. Сначала билет, потом ошибка.

`price <= 0` — цена не годится. `return Ticket{}, errors.New("цена")` отдаёт нулевой билет и ошибку с текстом `"цена"`. Нулевой struct пишут пустыми скобками: `Ticket{}`.

Если цена больше нуля, `return Ticket{Price: price}, nil` отдаёт заполненный билет. `nil` на месте ошибки значит: ошибки нет.

Вызов принимает оба значения:

```go
ticket, err := NewTicket(0)
if err != nil {
	fmt.Println(err.Error())
}
```

`err.Error()` возвращает текст ошибки. Для цены `0` это строка `"цена"`. До печати поле `ticket.Price` смотреть незачем: инстанс нулевой, данные не прошли проверку.

Проверок в одной функции может быть несколько. Каждая смотрит своё условие и возвращает свою ошибку. Дальше по коду выполнение этой функции не идёт: `return` уже отдал результат.

## Что запомнить

- Конструктор с проверкой возвращает `(Тип, error)`.
- Плохие данные: нулевой struct и `errors.New("текст")`.
- Хорошие данные: заполненный struct и `nil`.
- Текст ошибки читают методом `Error`.
