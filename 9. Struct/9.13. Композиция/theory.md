# 9.13. Композиция

Композиция — сборка одного типа из другого. Внешний struct хранит внутренний как поле. Так описание администратора включает описание пользователя и добавляет свои поля.

Поле с именем читают через это имя.

```go
type User struct {
	Name string
}

type Admin struct {
	User  User
	Level int
}
```

Второе поле `User` имеет имя `User` и тип `User`. Имя и тип здесь совпали по буквам. Это обычное поле.

```go
admin := Admin{
	User:  User{Name: "Ada"},
	Level: 2,
}
fmt.Println(admin.User.Name)
```

`admin.User` — внутренний `User`. `admin.User.Name` — его имя, строка `"Ada"`. `admin.Level` — поле самого `Admin`, число `2`.

## Встраивание

Встраивание (embedding) — поле без своего имени. В описании остаётся только тип. Ниже тот же `Admin` записан заново: поле `User` стоит без имени.

```go
type Admin struct {
	User
	Level int
}
```

`User` в этой записи — встроенное поле. Его поля доступны по короткому имени у внешнего значения.

```go
admin := Admin{
	User:  User{Name: "Ada"},
	Level: 2,
}
fmt.Println(admin.Name)
```

`admin.Name` читает `Name` встроенного `User`. Это то же поле, что `admin.User.Name`. В литерале ключ по-прежнему имя типа: `User: User{Name: "Ada"}`.

`Level` объявлен у `Admin`, поэтому его читают как `admin.Level`. Короткие имена встроенных полей и собственные поля внешнего struct стоят рядом.

Внутренний тип может быть любым struct из этого пакета. Внешний добавляет к нему свои поля и пользуется его полями по короткому имени.

## Что запомнить

- Композиция: внешний struct хранит другой struct полем.
- Поле с именем читают так: `admin.User.Name`.
- Встраивание — поле без имени, в описании только тип.
- Поле встроенного struct читают коротко: `admin.Name`.
